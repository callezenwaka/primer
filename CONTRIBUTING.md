# Contributing to primer

## Development setup

**Prerequisites:** Rust toolchain via [rustup](https://rustup.rs).

```sh
git clone https://github.com/barestripehq/primer
cd primer
cargo build                      # default build, no AI
cargo build --features ai        # build with AI summary layer
```

## Running tests

```sh
cargo test                       # full test suite
cargo test --features ai         # include AI-gated tests
```

## Linting

```sh
cargo fmt --check                # check formatting
cargo clippy -- -D warnings      # lint (warnings as errors)
```

Fix formatting in place with `cargo fmt`.

## Project structure

This is a Cargo workspace with two members:

```
cli/               — primer binary (the user-facing CLI)
  src/
    main.rs        — CLI entry point (clap)
    shim.rs        — argv parsing, shim dispatch, pass-through logic
    manifest.rs    — manifest file parsers (diff and full-file)
    config.rs      — ~/.primer/config.toml read/write
    cache.rs       — 24h local cache keyed by ecosystem+package+version
    engine/
      osv.rs       — OSV API client
    cli/
      hook.rs      — `primer hook install` / `primer hook check`
      init.rs      — shim setup and teardown
      scan.rs      — interactive scan flow
    summary/       — AI summary layer (feature-gated)
      download.rs  — model download via hf-hub
      infer.rs     — GGUF inference via candle

app/               — primer-app webhook server (GitHub App, Tier 1)
  src/
    main.rs        — axum entry point (listens on $LISTEN_ADDR, default 0.0.0.0:8080)
    webhook.rs     — HMAC-SHA256 signature verification, push/pull_request dispatch
    runner.rs      — shallow clone, runs `primer scan`, posts results
    github.rs      — GitHub API client (Check Runs, PR comments, SARIF upload)
```

`cargo build` compiles only `cli` by default. Use `cargo build --workspace` to build both.

## Releasing

primer uses [`cargo-release`](https://github.com/crate-ci/cargo-release) to cut releases. Binaries are built and distributed by [cargo-dist](https://opensource.axo.dev/cargo-dist/) via GitHub Actions.

### One-time setup

```sh
cargo install cargo-release
```

### Cutting a release

| Change type | Command |
|-------------|---------|
| Bug fix | `cargo release patch` |
| New feature (backwards-compatible) | `cargo release minor` |
| Breaking change | `cargo release major` |

`cargo release` will:
1. Bump the version in `cli/Cargo.toml`
2. Commit with `chore: release <version>`
3. Create an annotated git tag `v<version>`
4. Push the commit and tag to `origin`

The pushed tag triggers the GitHub Actions release workflow, which cross-compiles binaries for all five targets and publishes a GitHub Release with shell and PowerShell installers.

### What not to do

- Do not edit the version in `cli/Cargo.toml` manually before releasing — `cargo release` handles it.
- Do not push a tag manually — let `cargo release` create it so it stays in sync with the `Cargo.toml` bump commit.
- Do not edit `.github/workflows/release.yml` by hand — it is generated by `cargo dist generate` and validated at runtime.

## Docs

The `docs/` directory is bundled into the `primer-app` Docker image and served by Cloud Run at `primer.barestripe.com` — no build step. A push to `main` that touches `app/**`, `cli/**`, `Dockerfile`, or `Cargo.toml`/`Cargo.lock` triggers the deploy workflow.

### Structure

| Path | URL | Purpose |
|------|-----|---------|
| `docs/index.html` | `/` | Marketing landing page |
| `docs/index/` | `/index/` | Docs home (sidebar layout) |
| `docs/<slug>/` | `/<slug>/` | Individual doc pages |

Shared files: `docs/components.js` (`<primer-doc-layout>` web component) and `docs/content.css` (typography).

### Local development

```sh
# Option 1 — primer-app (matches production exactly)
DOCS_DIR=docs cargo run -p primer-app   # serves at localhost:8080

# Option 2 — plain HTTP server (docs only)
python3 -m http.server 3000 --directory docs
```

Do not open HTML files directly via `file://` — relative paths for `components.js` and `content.css` only resolve correctly over HTTP.

### Adding a doc page

1. Create `docs/<slug>/index.html` using `<primer-doc-layout active="<slug>">`.
2. Add the slug to the `NAV` array in `docs/components.js`.
3. Add a nav card to `docs/index/index.html` if it belongs in the overview grid.

## Local development — primer-app (webhook server)

Set the three required environment variables (obtain values from the project maintainer or register your own GitHub App):

```sh
export WEBHOOK_SECRET=<secret>
export APP_ID=<app-id>
export APP_PRIVATE_KEY=<pem-contents>
```

Start the server:

```sh
DOCS_DIR=docs cargo run -p primer-app   # listens on localhost:8080
```

Forward live GitHub webhook events to the local server using the GitHub CLI:

```sh
gh webhook forward \
  --repo=barestripehq/primer \
  --events=push,pull_request \
  --url=http://localhost:8080/webhook
```

GitHub delivers each event to `localhost:8080/webhook` exactly as it would to production. The server verifies the HMAC-SHA256 signature, clones the repo at the target SHA, runs `primer scan`, and posts results back via the GitHub API.

## CI

Two workflows run on every push to `main` and on pull requests:

| Workflow | File | What it checks |
|----------|------|---------------|
| CI | `.github/workflows/ci.yml` | `cargo test`, `cargo fmt`, `cargo clippy` on ubuntu / macOS / Windows |
| Release | `.github/workflows/release.yml` | Triggered by `v*` tags only — builds and publishes binaries |
